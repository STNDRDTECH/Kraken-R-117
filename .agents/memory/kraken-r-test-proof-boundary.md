---
name: Kraken-R test-proof boundary
description: Kraken-R tests prove bounded synthetic reducers and security boundaries, not real-repository causal learning or a sustained autonomous loop.
---

Kraken-R's test suite has broad subsystem coverage, but most records and settlements are manually constructed. Grounded execution tests prove isolation and attestation for tiny supplied fixtures; they do not prove real-repository repair, external causal improvement, exactly-once side effects, or deployment behavior. A whole-loop test must begin with a real task and repository, independently verify the outcome, apply bounded learning, run later ticks, and compare against controls.

**Why:** Subsystem passes can look like end-to-end evidence even when task integrity, provider execution, settlement, adaptation, and later outcomes are never connected in one sustained run.

**How to apply:** Treat real-corpus reproduction, randomized frozen/shuffled controls, crash/restart/concurrency checks, network and sandbox realism, and clean-environment test collection as entry gates before any authority or Stage 12 claim.
